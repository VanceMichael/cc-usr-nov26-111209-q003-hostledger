# 主机交付格式

原始 HTTP /file 返回 RDW 流。仓库 .hex 只为便于审阅，以 HEX 换行后十六进制保存相同字节；inspect 同时接受两种输入。每条记录以两字节大端总长度和两字节零保留位开始，长度包含四字节 RDW，offset 从文件第零字节算。载荷文字 cp037，不含 BOM。

H 头：类型一字节、布局版本两字节、业务批次号五字节。T 尾：类型一字节、明细数六位文本数字、总额十位文本数字，尾数以布局最小小数单位表示有符号净额；本地例子净额为 1184（12.34 减 0.50）。N 普通和 C 温控记录的字段跨度列于 layouts.json；所有偏移以载荷起点算。id 七字节。amount 采用 COMP-3，末半字节 C/F 为正、D 为负，其余半字节只能 0-9，01版三字节两位小数，02版四字节三位小数。N 的 count 为 cp037 数字，0-4 组，每组两字节货类，剩余只允许 cp037 空格；C 同字节区间为三位温度，布局不同时不兼用 N 的组。所有必需字段不得越界。

文件名不是业务身份，同一业务批次可补发，但不同内容须保留原始关系。控制明细数统计 N+C，不含 H/T，普通和温控各有可计算的分类型数。batch 必须一个 H 开始一个 T 结束，不允许中途嵌套。错误记录原始跨度应可见，未核对成功的批次不能作为正式明细使用。这里不实现完整 COBOL 语法，layouts.json 是本项目受支持布局表。

## 本项目接收判定

- 布局由 H 的两字节版本和记录类型字节（H/N/C/T）联合选择；版本未知时整份文件只做隔离，不假定任何字段跨度。
- 头尾控制核对：明细数与 N+C 条数相等，总额与逐票 COMP-3 金额按尾记录小数位精确合计相等。合计使用带符号原始数字，不使用浮点。
- 每票保留记录 RDW 起点、载荷起点、布局版本和每个字段的绝对字节范围；字段越界整票隔离。
- 空格、零值和未提供是三种事实：件数空格或温度全空格记为未提供并隔离；cp037 数字 0 是有效的零；未声明重复组时剩余字节必须是 cp037 空格并记录为填充。
- 重复组必须在载荷内完整；件数超过 0-4、组区越界或货类编码不可打印都隔离该票。
- 整份文件只有在头尾结构、控制数和全部明细都通过时才进入正式查询；隔离原因与原始十六进制保留供运营复核。
